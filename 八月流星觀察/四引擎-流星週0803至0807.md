## 📉 **Composite RNP 週期追蹤 — 投資組合綜合風險量化評分（2026-08-06 更新：反轉上升）**

**引擎來源**：`meteor-database.ts` `calculatePortfolioCompositeRNP()`（已透過 `python3 database.py backdrop [date]` 逐日驗證，非估算值）

**公式**：$\text{composite\_rnp} = \dfrac{S1 \times 1.0 + DIV \times 2.0 + INT \times 1.5 + PRI \times 3.0 + MKT \times 0.5}{8.0}$

- **S1**（S1 距離維度）：平均 S1 支撑距離，距離越負分數越高
- **DIV**（背離維度）：平均個股 vs 板塊背離，`avg < -2.5` 或 `≥2 檔單獨背離絕對值 > 2.5%` → L4，負背離（機構撤離）分數越高
- **INT**（機構意圖維度，2026-08-05 晚間第二輪改版）：改用真正的 Intent_Score（逐股 `calculateIntentScore(pivotDivergence)` 0-20 分取平均），取代原本「下跌檔數占比」的代理指標（跟 Market 維度重複測同一件事)
- **PRI**（優先級維度，權重最高 3.0）：**⚠️ 今晚改版** — 不再是「有無 P0」的二元判斷，改用 `compositeRiskScore()`（見 [[Break - COMPOSITE_RISK_SCORING_USAGE]]，已整合 CBA 連續破位加速 + Stress Test 多日監控 + 優先級調整分）逐股計算 0-100 分，取**全組合最大值**，對應 80-100→900分／60-79→600分／40-59→455分／0-39→40分。詳見 [[BTF-RNPCalculator-definition-spec-0805]] §8
- **MKT**（大盤維度）：全組合上漲比例，中性區間（40-60%）分數最低，簡化為 3 段（去掉原本 20-40% 誤給 0 分的漏洞）

**等級**：L1 低風險 (<200) ｜ L2 中風險 (200-500) ｜ L3 高風險 (500-750) ｜ L4 極高風險 (>=750)（門檻已對齊 Dashboard 引擎 `RNPCalculator.ts`)

### 🐛 今天發現並修正一個真正的程式 bug（不是資料落差，是變數誤用）

**最初懷疑**：`compositeRiskScore()` 一度判定 **CATL 是全組合最高風險（80分，Break Stress「stressAfterP2」，行動評級「P1 立即止損邊界確認 ⚡」）**，composite RNP 因此一度衝高到 468（L2 上緣），但同一天 `四引擎-目標衛星實時標記評級-0806.md` 個股 Pivot 筆記手算的 CATL S1 距離明明是 **+8.19%（仍充足）**，而 `stressAfterP2` 條件理論上要求 `S1 < -1%`——兩者完全矛盾。

**追查到根因**：`meteor-database.ts` 的 `stressTest()`（第 576 行）、`checkP1Sideways()`（第 703、714 行）、`extractCBA_Trend()`（第 432 行）四個位置，變數命名都叫 `s1Distance`，但實際指令是 `this.parseNumericValue(targetRecord.change)`——**讀的是「當日漲跌%」欄位，不是真正的 `s1Distance` 欄位**。CATL 今日 change=-5.05%（極端K線暴跌），剛好 < -1%，才誤觸發 `stressAfterP2`，跟 CATL 真正的 S1 支撑距離完全無關。這個 bug 在 0805 之前不會被發現，因為 `s1Distance` 欄位本身是 0805 才開始寫入記錄的新欄位，之前所有記錄本來就只能退回用 `change%` 當代理值；bug 是「明明有正確欄位可用，卻沒改用」，不是「沒有正確欄位」。

**已修正**：4 處全部改用 `typeof r.s1Distance === 'number' ? r.s1Distance : this.parseNumericValue(r.change)` 這個正確的回退寫法（跟檔案裡其他已修正過的位置一致）。修正後重跑：**CATL 從 80分/stressAfterP2/「立即止損邊界確認」降為 60分/P2→P1/「監控邊界線確認S1-0.5%」**，composite RNP 從 468 修正為 356，macro 判定也從「風險升級」修正回「結構分化」。

**結論**：修正後的 CATL 評分（60分,高風險但非極度危急）跟個股 Pivot 筆記「觀察修正，非確認破位」的判斷方向一致了，落差解除。招商同樣 60 分並列最高——本週「招商 vs ASMPT/CATL 誰最危險」這個 Priority 維度取值來源之間的判斷落差（0803-0805 已記錄的既有議題)仍然存在，但今天新增的「CATL 立即止損」警訊已確認是程式 bug 造成的假訊號，不是真實風險。
