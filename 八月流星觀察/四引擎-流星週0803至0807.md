## 📉 **Composite RNP 週期追蹤 — 投資組合綜合風險量化評分（2026-08-07 更新：BTF/Vault 雙引擎徹底同步）**

**引擎來源**：`meteor-database.ts` `calculatePortfolioCompositeRNP()`（已透過 `python3 database.py backdrop [date]` 逐日驗證，非估算值）；今日起與 BTF Dashboard 的 `RNPCalculator.ts` 全天候即時交叉驗證，兩者對同一份即時快照全程算出同一分數

**公式**：$\text{composite\_rnp} = \dfrac{S1 \times 1.0 + DIV \times 2.0 + INT \times 1.5 + PRI \times 3.0 + MKT \times 0.5}{8.0}$

- **S1**（S1 距離維度）：平均 S1 支撑距離，距離越負分數越高
- **DIV**（背離維度）：平均個股 vs 板塊背離，`avg < -2.5` 或 `≥2 檔單獨背離絕對值 > 2.5%` → L4，負背離（機構撤離）分數越高
- **INT**（機構意圖維度）：改用真正的 Intent_Score（逐股 `calculateIntentScore(pivotDivergence)` 0-20 分取平均），取代原本「下跌檔數占比」的代理指標
- **PRI**（優先級維度，權重最高 3.0）：不是「有無 P0」的二元判斷，改用 `compositeRiskScore()`（已整合 CBA 連續破位加速 + Stress Test 多日監控 + 優先級調整分）逐股計算 0-100 分，取**全組合最大值**，對應 80-100→900分／60-79→600分／40-59→455分／0-39→40分
- **MKT**（大盤維度）：全組合上漲比例，中性區間（40-60%）分數最低，簡化為 3 段

**等級**：L1 低風險 (<200) ｜ L2 中風險 (200-500) ｜ L3 高風險 (500-750) ｜ L4 極高風險 (>=750)（門檻已對齊 Dashboard 引擎 `RNPCalculator.ts`)

### 🔧 今天完成：BTF Dashboard 與 Vault 引擎的 Priority/Intent 維度徹底同步

**問題**：Vault 端 `portfolio-data.json` 內嵌的 `portfolio_rnp` 顯示 **427**，但同一天同一份快照，BTF Dashboard 即時 API `/api/dashboard/overview` 顯示 **493**——兩邊算法應該一致，卻對不上。

**根因**：0805 那次「用 compositeRiskScore 取代 Priority 維度、用真實 intentScore 取代 Intent 維度」的改版，**只做進了 `meteor-database.ts`，從未同步回 BTF 的 `RNPCalculator.ts`/`PortfolioSync.ts`**。BTF 那邊 Priority 維度仍是「有沒有任一檔 P0 旗標」的二元判斷（`p0>0→900`，不管風險分數多少都給滿分），Intent 維度仍是舊的「下跌檔數占比」代理公式。逐項代入驗算，Vault 算出 427、BTF 算出 493，跟兩邊各自的公式都對得上，純粹是兩套公式沒同步。

**修正**：
- `BTF/src/calculators/RNPCalculator.ts`：`calculatePriority()` 改吃 `maxRiskScore`，套用跟 `dimensionPriorityRNP()` 一致的 900/600/455/40 級距；`level`（P0/P1/P2 標籤）仍用旗標判斷，因為場景偵測邏輯需要真實旗標數，不是分數
- `BTF/src/services/PortfolioSync.ts`：`transformToRNPDimensions()` 改用逐股真實 `intentScore` 平均值，並新增 `max_risk_score` 欄位
- **新增資料管線**：`calculate-macro-backdrop.ts` 新增 `syncRiskScoresToPortfolioJson()`，每次 `database.py backdrop` 執行時把逐股 `intentScore`/`riskScore` 寫回 `portfolio-data.json`，供 BTF 讀取
- **順手抓到第二個 bug**：`portfolio-data-updater.py`（20秒即時報價刷新）每次都整包重建股票物件，會把剛寫入的 `intentScore`/`riskScore` 洗掉。修正：`save_portfolio_data()` 存檔前先讀舊檔把這兩個欄位帶過來
- **一度多寫的重複呼叫**：曾另外加一個 `run_backdrop_calc()` 想讓這兩個欄位每分鐘刷新，後來發現 `update-summary-with-ollama.py` 的 `get_macro_backdrop()` 本來就會呼叫同一支 `calculate-macro-backdrop.ts`，跟 `llm_update_summary()` 同頻率（約每分鐘）——**根本不需要額外加**，已移除重複呼叫

**驗證**：修正後全天候多次交叉比對，Vault 手算與 BTF 即時 API 對同一份快照全部算出同一個數字（343），且 `intentScore`/`riskScore` 確認會跟著即時股價每分鐘自動刷新（不需手動重跑）。
